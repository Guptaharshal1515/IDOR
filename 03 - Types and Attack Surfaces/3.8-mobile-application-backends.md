# 3.8 Mobile Application Backends

Mobile applications rely on APIs for profiles, messages, payments, files, and device actions. The application package and traffic may reveal endpoint patterns, but the central issue remains server-side authorization.

A mobile client may hide controls based on role, yet an attacker can send requests directly. A value stored in local application state is not trustworthy merely because it came from the official app. The API must derive identity from the verified token and authorize the requested object.

Assessment should consider different mobile versions, offline synchronization, device registration, push links, and endpoints not visible in the current UI. Use approved accounts and avoid safety-critical controls outside a specifically authorized environment.
