# 3.4 GraphQL IDOR

GraphQL often uses one `/graphql` endpoint. Object references then appear inside query variables, fields, aliases, and mutation inputs. The authorization problem is still the same.

```json
{"query":"mutation Delete($id: ID!) { deleteDocument(id: $id) }","variables":{"id":"document-200"}}
```

The resolver must verify that the authenticated principal may delete `document-200`. Checking only that the user may call `deleteDocument` is function-level authorization and is not enough. The resolver must authorize the particular document.

Assessment should cover queries, mutations, aliases, nested resolvers, connections, and batch operations where permitted. A field may be protected while a related resolver or mutation is not, creating inconsistent authorization.
