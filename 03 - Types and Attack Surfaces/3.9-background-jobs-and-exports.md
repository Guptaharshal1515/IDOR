# 3.9 Background Jobs and Exports

Long-running operations create a job, export, report, or notification that can be retrieved later using a job ID. Developers may protect the request that starts the operation but forget to authorize the status or download endpoint.

```text
GET /exports/job-123/status
GET /exports/job-123/download
GET /reports/generated-88
```

The server must confirm that the current principal may view the job and its result. It should consider whether a job continues after access is revoked, whether files expire, and whether queued work contains data from multiple tenants.

Testing should create a small approved export for Account A, then attempt to access its status and result as Account B. Verify both the response and downloaded contents.
