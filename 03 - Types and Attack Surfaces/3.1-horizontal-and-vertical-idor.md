# 3.1 Horizontal and Vertical IDOR

## Horizontal IDOR

Horizontal access means two users have a similar privilege level, but each user should be restricted to their own objects. A horizontal IDOR occurs when User A changes an object reference and accesses an object belonging to User B.

```http
GET /api/orders/501 HTTP/1.1
Cookie: session=customer-a
```

If order `501` belongs to Customer B and the server returns it to Customer A, the application has failed to check ownership. Both users may be ordinary customers; the problem is the missing relationship between the current user and the requested order.

Horizontal IDORs commonly expose profiles, invoices, support tickets, messages, uploaded documents, or account settings. They are especially serious when the same weakness works across organizational or tenant boundaries.

## Vertical IDOR

Vertical access concerns different privilege levels. A vertical IDOR occurs when a lower-privileged user accesses an object or operation intended for an administrator, manager, or support role. The report should identify whether the failure involved the endpoint, the object, or both.

Test horizontal access with two accounts of the same role. Test vertical access with accounts of different roles, using harmless test objects. Do not assume that an administrator can access every object; many systems still require tenant or business-unit restrictions.
