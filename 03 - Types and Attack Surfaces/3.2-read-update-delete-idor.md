# 3.2 Read, Update, and Delete IDOR

The HTTP method does not determine seriousness. The action performed on the object determines the main impact.

## Read-based IDOR

A read-based IDOR returns another user’s data through a page, API response, download, image, or export. Examples include viewing another customer’s invoice, reading a private message, or downloading a case attachment. The primary impact is usually confidentiality, but exposed data may enable fraud or account takeover.

## Update-based IDOR

An update-based IDOR allows a user to change an object they do not own, such as another user’s shipping address, order status, or support ticket. A safe test uses a dedicated test record and verifies that an unauthorized request causes no state change.

## Delete-based IDOR

A delete-based IDOR allows deletion or destructive state changes to another user’s object. Examples include deleting a document, revoking access, or canceling an order. This affects availability and integrity and may create recovery or legal problems.

The same endpoint family may expose more than one defect. Test each action independently rather than assuming that fixing read access fixes write access.
