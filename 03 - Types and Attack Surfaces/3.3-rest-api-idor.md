# 3.3 REST API IDOR

REST APIs place object identifiers in URL paths, query parameters, request bodies, or headers. Visibility of an identifier is not itself a vulnerability; the API becomes vulnerable when it uses that identifier without checking access to the selected object.

```text
GET   /api/invoices/1042
PATCH /api/orders/8801
DELETE /api/documents/314
GET   /api/users/22/notifications
```

A secure API checks authorization for the object on every request, including bulk endpoints and alternate API versions. Filtering records in the client or returning only allowed IDs from the first page is not sufficient because a client can construct a new request directly.

During assessment, compare the owner’s response with a second authorized account. Check status codes, response fields, pagination, nested objects, and side effects. A generic success message may still indicate a vulnerability if the underlying object changed.
